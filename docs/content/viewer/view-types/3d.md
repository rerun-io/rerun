Use a 3D view to explore point clouds, meshes, camera poses, and other 3D geometry.
It is useful for checking scene reconstructions, robot motion, and the alignment of data from different sensors.

See the [`Spatial3DView` reference](../../reference/types/views/spatial3d_view.md) for properties and examples.

## Data for this view

Use 3D geometry such as points, meshes, depth images, transforms, and camera poses.

## Configure the view

### Control the 3D camera

In a 3D view, the camera that you look through is called the _eye_.
You can set the eye from code with the `eye_controls` parameter of [`Spatial3DView`](../../reference/types/views/spatial3d_view.md), which takes an `EyeControls3D` blueprint archetype (see [`eye_controls`](../../reference/types/views/spatial3d_view.md#eye_controls)).

#### Set the eye position and look target

snippet: views/spatial3d_eye_controls

`EyeControls3D` has these fields:

| Field             | Meaning                                                                                               |
|-------------------|-------------------------------------------------------------------------------------------------------|
| `kind`            | `rrb.Eye3DKind.Orbital` (default) or `rrb.Eye3DKind.FirstPerson`.                                     |
| `position`        | The position of the eye.                                                                              |
| `look_target`     | The point that the eye looks at. For an orbital eye, this is also the point it orbits around.         |
| `eye_up`          | The up axis of the eye, in world space. Defaults to the up axis of the scene, or +Z if there is none. |
| `speed`           | Translation speed when you move with the WASDQE keys.                                                 |
| `tracking_entity` | An entity that the eye follows. See below.                                                            |
| `spin_speed`      | Spin the eye around the up axis at this speed. Defaults to 0 (no spinning).                           |

The scene up axis comes from [`ViewCoordinates`](../../reference/types/archetypes/view_coordinates.md).
For example, log `rr.ViewCoordinates.RIGHT_HAND_Z_UP` as static data on the view's origin entity to make +Z the up axis.

The blueprint sets the eye when the Viewer receives it.
After that, the user can move the eye freely.
Send the blueprint again to move the eye back.

#### Orbital or first-person controls

- `Orbital`: the eye rotates around `look_target`.
  Scroll zooms toward and away from it.
- `FirstPerson`: the eye rotates around its own position, like in a first-person game.
  Use WASD and QE to move.

```python
rrb.Spatial3DView(
    origin="/world",
    eye_controls=rrb.EyeControls3D(kind=rrb.Eye3DKind.FirstPerson, speed=20.0),
)
```

You can also switch between the two in the Viewer: select the view and change the eye kind in the selection panel.

#### Follow an entity

Set `tracking_entity` to make the eye follow an entity as it moves:

```python
rrb.Spatial3DView(
    origin="/world",
    eye_controls=rrb.EyeControls3D(tracking_entity="/world/robot"),
)
```

If the tracked entity is a camera (an entity with a [`Pinhole`](../../reference/types/archetypes/pinhole.md)), the eye takes over the pose of that camera, so you see the scene through it.

In the Viewer, you can start tracking an entity with Alt + double-click on it, or with "Set as eye tracked" in its context menu.
Double-click an entity to focus on it, and double-click the background to reset the eye.

#### Camera limitations

There is currently no way to:

- lock the eye, so that the user cannot move it,
- limit how far the user can zoom in or out.

See [missing features](../../development/roadmap.md#missing-features).

## Common tasks

### Control mesh appearance

This section explains how [`Mesh3D`](../../reference/types/archetypes/mesh3d.md) and [`Asset3D`](../../reference/types/archetypes/asset3d.md) are shaded, and which settings you can change.

#### Lighting

The 3D view uses simple, fixed lighting: two directional lights and some ambient light.
You cannot add lights, move them, or turn on shadows.
There are no material properties, such as roughness, metallic surfaces, or specular highlights.
See [missing features](../../development/roadmap.md#missing-features).

#### Why does my mesh look flat or unlit?

Lighting needs vertex normals.

- `Mesh3D` without `vertex_normals` is drawn _unlit_: every triangle gets its plain color, so the shape is hard to see.
  Pass `vertex_normals` to get shading.
- `Asset3D` computes flat normals for meshes in the file that have none.
  To draw an asset unlit, give it all-zero vertex normals.

To compute smooth vertex normals for a `Mesh3D` yourself, you can use a library such as [trimesh](https://trimesh.org/):

```python
import trimesh

mesh = trimesh.load("model.obj", force="mesh")
rr.log(
    "mesh",
    rr.Mesh3D(
        vertex_positions=mesh.vertices,
        triangle_indices=mesh.faces,
        vertex_normals=mesh.vertex_normals,
    ),
)
```

#### Colors and textures

- `vertex_colors`: one color per vertex.
- `albedo_factor`: one color for the whole mesh.
  It is multiplied with the vertex colors and the texture.
- `albedo_texture` together with `vertex_texcoords`: a texture image.

See the [`Mesh3D` reference](../../reference/types/archetypes/mesh3d.md) for an example of a textured mesh.
For `Asset3D`, colors and textures come from the file, and you can tint the whole asset with `albedo_factor`.

#### Transparency

The only way to make a mesh transparent is the alpha channel of `albedo_factor`:

```python
rr.log("mesh", rr.Mesh3D(vertex_positions=positions, triangle_indices=triangles, albedo_factor=[255, 255, 255, 128]))
```

The alpha channel of `vertex_colors` and of the texture is ignored.

#### Front and back faces

By default, both sides of each triangle are drawn.
Set `face_rendering` to `"Front"` or `"Back"` to draw only one side.
Front faces have their vertices in counter-clockwise order.

```python
rr.Mesh3D(vertex_positions=positions, triangle_indices=triangles, face_rendering="Front")
```

### Depth images, heightmaps, and voxels

#### Depth image to 3D point cloud

Log a [`DepthImage`](../../reference/types/archetypes/depth_image.md) under an entity with a [`Pinhole`](../../reference/types/archetypes/pinhole.md) camera.
The 3D view then projects every pixel into 3D, so you get a point cloud without computing it yourself.
Set `meter` to the number of depth units per meter (for example `1000` for depth in millimeters).

snippet: archetypes/depth_image_3d

To place the camera in the world, log a [`Transform3D`](../../reference/types/archetypes/transform3d.md) to the camera entity.
The same depth image is also shown as an image in a 2D view.
`point_fill_ratio` sets the size of the points, and `colormap` and `depth_range` set their colors.

#### Heightmaps and elevation grids

There is no built-in heightmap or surface archetype.
Build a [`Mesh3D`](../../reference/types/archetypes/mesh3d.md) from the grid: one vertex per cell, and two triangles per grid square.

snippet: views/spatial3d_heightmap

The mesh has no normals, so it is drawn without shading.
Pass `vertex_normals` to get lighting, and `vertex_colors` to color it by height.
See [Control mesh appearance](3d.md#control-mesh-appearance).

For a quick look, you can instead log the grid as a [`Points3D`](../../reference/types/archetypes/points3d.md) with the same `positions`, or as a 2D [`Image`](../../reference/types/archetypes/image.md) or [`DepthImage`](../../reference/types/archetypes/depth_image.md) with a colormap.

#### Voxels

For sparse voxel grids, such as occupancy maps, use [`VoxelGridMap`](../../reference/types/archetypes/voxel_grid_map.md).
It takes integer voxel indices, a voxel size, and optional values with a colormap.
`VoxelGridMap` is unstable: its data format may change in future releases.

snippet: archetypes/voxel_grid_map_simple

You can also draw voxels as [`Boxes3D`](../../reference/types/archetypes/boxes3d.md) with `fill_mode="solid"`, one box per voxel.
This works for a moderate number of voxels.

#### Dense volumes

For dense 3D scalar fields, such as CT or MRI scans, signed distance fields, or occupancy probabilities, use [`Volume3D`](../../reference/types/archetypes/volume3d.md).
It is rendered with ray marching.
`Volume3D` is unstable: its data format may change in future releases.

snippet: archetypes/volume3d_simple

For 2D occupancy grids, for example from a robot's map, see [`GridMap`](../../reference/types/archetypes/grid_map.md).

### Covariance ellipsoids in 3D

Use [`Ellipsoids3D`](../../reference/types/archetypes/ellipsoids3d.md).
To draw a 3×3 covariance matrix, take its eigendecomposition:

- the half sizes of the ellipsoid are `k * sqrt(eigenvalues)`, where `k` is the number of standard deviations,
- the rotation is the matrix of eigenvectors (one eigenvector per column).

Put the rotation and the mean in a [`Transform3D`](../../reference/types/archetypes/transform3d.md) on the same entity:

snippet: views/spatial3d_covariance

To draw many ellipsoids in one entity, pass `centers` and one rotation per ellipsoid with `quaternions` instead.
You can convert a rotation matrix to a quaternion with, for example, `scipy.spatial.transform.Rotation.from_matrix(eigenvectors).as_quat()` (which returns `xyzw`).
If `np.linalg.det(eigenvectors)` is negative, flip the sign of one column first, so that the matrix is a rotation.

For other uncertainty visualizations, see [2D covariance ellipses](2d.md#covariance-ellipses-in-2d) and [time series error bands](time-series.md#error-bands-and-uncertainty).

### Gaussian splats

[`GaussianSplats3D`](../../reference/types/archetypes/gaussian_splats3d.md) draws 3D Gaussians with a center, per-axis scales (standard deviations), a rotation, and a color with opacity.
It is meant for 3D Gaussian Splatting (3DGS) reconstructions, but you can also use it to show many probability distributions at once.
`GaussianSplats3D` is unstable: its data format may change in future releases.

3DGS `.ply` files are loaded as `GaussianSplats3D` when you open them in the Viewer, or log them with `rr.log_file_from_path`.

### Color a point cloud by height or intensity

[`Points3D`](../../reference/types/archetypes/points3d.md) has no colormap and no scalar-to-color input.
To color points by a value (height, intensity, temperature, …), compute one RGB(A) color per point yourself and pass it as `colors`.
For example, with a matplotlib colormap:

```python
import matplotlib
import numpy as np
import rerun as rr

heights = positions[:, 2]
normalized = (heights - heights.min()) / max(np.ptp(heights), 1e-9)
colors = matplotlib.colormaps["viridis"](normalized)  # RGBA floats in 0-1

rr.log("points", rr.Points3D(positions, colors=colors))
```

To switch between several colorings without logging the points again, log each color set as its own component and use [component mappings](../view-concepts/component-mappings.md).
